أوضاع الشبكة في Docker

يوفّر Docker عدة مشغّلات شبكة (network drivers)، يناسب كلٌّ منها حالات استخدام محددة.

Bridge (الوضع الافتراضي)

ينشئ وضع bridge شبكة معزولة للحاويات الموجودة على المضيف (host) نفسه:

docker network create --driver bridge my-network
docker run --network my-network --name app myapp
docker run --network my-network --name db mysql

تستطيع الحاويات المتصلة بشبكة bridge نفسها التواصل فيما بينها باستخدام اسم الحاوية كاسم مضيف (hostname).

Host

يلغي وضع host العزل الشبكي، إذ تستخدم الحاوية شبكة المضيف مباشرة:

docker run --network host nginx

مفيد للحصول على أقصى أداء، لكن دون أي عزل.

Overlay

في عناقيد Docker Swarm، تتيح شبكة overlay التواصل بين الحاويات الموزعة على عُقد مختلفة:

docker network create --driver overlay --attachable my-overlay

خادم DNS الداخلي

يتضمن Docker خادم DNS مدمجاً يتيح الوصول إلى الخدمات بأسمائها:

services:
  app:
    networks:
      - frontend
      - backend
  nginx:
    networks:
      - frontend
  db:
    networks:
      - backend

networks:
  frontend:
  backend:

أفضل ممارسات الشبكات

  • اعزل الخدمات حسب الشبكة (frontend، backend، monitoring)
  • استخدم شبكات داخلية للخدمات غير المكشوفة للخارج
  • وثّق طوبولوجيا الشبكات لديك
  • قلّص المنافذ (ports) المكشوفة إلى الحد الأدنى الضروري
