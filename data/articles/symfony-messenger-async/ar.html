Symfony Messenger: المعالجة غير المتزامنة بكل بساطة

يتيح مكوّن Messenger في Symfony فصل المعالجات الطويلة عن طلبات HTTP لتقديم تجربة مستخدم أفضل.

معمارية Message/Handler

// Message
class SendNotificationMessage
{
    public function __construct(
        public readonly int $userId,
        public readonly string $content,
    ) {}
}

// Handler
#[AsMessageHandler]
class SendNotificationHandler
{
    public function __construct(
        private NotificationService $notificationService,
    ) {}

    public function __invoke(SendNotificationMessage $message): void
    {
        $this->notificationService->send(
            $message->userId,
            $message->content,
        );
    }
}

إعداد وسائل النقل (transports)

# config/packages/messenger.yaml
framework:
    messenger:
        transports:
            async:
                dsn: '%env(MESSENGER_TRANSPORT_DSN)%'
                retry_strategy:
                    max_retries: 3
                    delay: 1000
                    multiplier: 2
            failed:
                dsn: 'doctrine://default?queue_name=failed'

        routing:
            App\Message\SendNotificationMessage: async
            App\Message\ProcessOrderMessage: async

إرسال الرسائل (dispatch)

class OrderController extends AbstractController
{
    #[Route('/order', methods: ['POST'])]
    public function create(
        MessageBusInterface $bus,
        Request $request,
    ): JsonResponse {
        // Fast synchronous processing
        $order = $this->orderService->create($request);

        // Asynchronous processing
        $bus->dispatch(new SendNotificationMessage(
            $order->getUserId(),
            "Order #{$order->getId()} confirmed"
        ));

        return $this->json($order, 201);
    }
}

الإشراف على الـ workers

  • استخدم systemd لإدارة الـ workers في بيئة الإنتاج
  • اضبط --time-limit لتفادي تسرّب الذاكرة
  • راقب قائمة الانتظار failed لتتبّع الرسائل التي فشلت معالجتها
  • استخدم الـ middleware الخاص بالتسجيل (logging) لتصحيح الأخطاء
